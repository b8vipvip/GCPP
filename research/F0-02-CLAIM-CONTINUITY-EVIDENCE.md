# F0-02 — Claim、Continuity 与 Evidence：第一轮形式化 / Claim, Continuity, and Evidence — Round 1 Formalization

> 状态 / Status: **F0 Research / Non-normative**  
> 默认语言 / Default language: **简体中文（zh-CN）**  
> 日期 / Date: **2026-08-29**

# 简体中文

## 1. 本轮要反驳什么

GCPP 初始研究假设：

```text
Entity
Relation
Continuity
Evidence
```

F0 Round 1 发现，这个四元组还不够严谨。

最重要的问题不是名字，而是语义：

1. `Relation` 如果直接写进图，容易被实现者当成“协议确认的事实”；
2. 但 GCPP 已固定 `VERIFIED != TRUE`，所以协议首先保存的其实是**Claim**；
3. `Continuity` 没有脱离 Scope / Facet / comparison criterion 的绝对定义；
4. `Evidence` 本身不是 verification result，更不是 policy decision；
5. partial / mixed provenance 要求 relation 有明确 scope；
6. conflicting provenance 要求 Claim 自己成为一等对象。

因此本轮结论是：

> **Provenance graph 应首先被理解为 evidence-backed claim graph，而不是一张未经限定的“事实图”。**

## 2. 为什么 Claim 必须是一等对象

考虑两个 Provider：

```text
Provider A claims: Output X was generated by Model A
Provider B claims: Output X was generated by Model B
```

协议不能直接把图写成：

```text
X generated-by A
X generated-by B
```

然后依靠消费者猜测哪条边是声明、哪条边是事实。

更合理的是：

```text
Claim C1
  proposition: X generated-by A
  asserted_by: Provider A
  evidence: E1

Claim C2
  proposition: X generated-by B
  asserted_by: Provider B
  evidence: E2
```

Verifier 可以分别评估 C1 与 C2。

这也使以下操作成为可能：

```text
support(C3, C1)
contradict(C4, C1)
supersede(C5, C1)
retract(C6, C1)
```

而不需要删除历史。

## 3. Prior Art 压力测试

### 3.1 W3C PROV

W3C PROV 已经拥有：

- Entity；
- Activity；
- Agent；
- derivation / generation / usage / influence；
- qualified relation；
- Bundle（provenance of provenance）。

所以 GCPP 不能宣称“图和 relation 是新的”。

GCPP 需要回答的是：

> 在生成式 AI 的 partial、mixed、semantic transform、claim-level evidence、conflict 和 cryptographic verification 场景中，如何避免把声明、证据、验证结果和政策结论混在一起？

### 3.2 Nanopublications

Nanopublication 已长期把一个小知识单元拆成：

```text
Assertion
Provenance of Assertion
Publication Info
```

这再次说明 Claim/Assertion 与其 provenance 分离是成熟思想。

GCPP 的研究重点不能是重新发明 assertion container，而应该是：

- provenance relation 的可验证 scope；
- transformation 后到底保留了什么；
- Evidence 的 proof boundary；
- claim-level 与 asset-level 来源如何组合；
- 多种现有 carrier 如何产生一致 Verification Vector。

### 3.3 IETF RATS

RFC 9334 提供了一个对 GCPP 极有价值的架构纪律：

```text
Evidence
   ↓ appraisal
Attestation / Verification Result
   ↓ relying-party policy
Application Decision
```

因此 GCPP 必须继续严格保持：

```text
EVIDENCE != VERIFICATION RESULT
VERIFICATION RESULT != POLICY DECISION
```

## 4. F0 第四项关键结论：Continuity 不能是裸 primitive

如果定义：

```text
Continuity(A, B)
```

它几乎没有严格含义。

### 4.1 翻译

英文 A 被翻译成中文 B。

- 字节不连续；
- token 不连续；
- 句法结构部分变化；
- 含义可能高度保留；
- 某些文化含义可能发生偏移；
- “B 确实由 A 翻译而来”是 historical/process provenance；
- “B 忠实保持 A 的全部语义”是另一个 claim。

不能只写：

```text
continuity = semantic
```

然后当成已验证事实。

### 4.2 摘要

100 篇材料 -> 摘要 S。

这里不是“每个来源都连续到了 S 的全部内容”。

更接近：

```text
Source A supports scope S1
Source B supports scope S2
Source C influenced paragraph P3
...
```

因此 continuity 必须与 source scope / target scope 结合。

### 4.3 模型训练

Dataset D 被用于训练 Model M：

```text
D used-in-training-of M
```

这是 historical dependency。

但它不推出：

```text
arbitrary Output O from M
preserves content from D
```

因此：

```text
HISTORICAL DEPENDENCY != CONTENT CONTINUITY
```

### 4.4 独立创作的相同文本

两个作者独立写出同一句短句：

```text
content(A) == content(B)
```

也不能推出：

```text
B derived-from A
```

因此：

```text
CONTENT CONTINUITY != PROVENANCE RELATION
```

## 5. Continuity 必须相对于 Facet / Projection / Scope

F0 Round 1 提出如下形式化研究框架。

设：

```text
S = source State
T = target State
π = projection / interpretation profile
σs = source scope selector
σt = target scope selector
R = claimed historical / transform relation
```

则一个 continuity claim 不是：

```text
C(S,T)
```

而是：

```text
C(S,T | π, σs, σt, R)
```

含义是：

> 在声明的 projection / facet 下，S 的指定 scope 与 T 的指定 scope 之间存在某种可验证保持或转换关系。

### 5.1 Projection / Facet

`π` 回答：

> 比较的到底是什么？

例如：

```text
raw bytes
normalized text
pixel plane
selected document structure
claim set
model component state
profile-defined property set
```

GCPP Core 不应该把这些全部写死。

### 5.2 Scope

`σ` 回答：

> Claim 到底适用于对象的哪一部分？

可能是：

- byte range；
- text span；
- paragraph / sentence；
- image region；
- audio/video interval；
- JSON subtree；
- dataset subset；
- model component；
- claim identifier；
- future selector profile。

Scope 的 encoding 应由 Profile 定义，但 **“relation 必须能够被 scope-qualified”** 很可能属于长期 Core 要求。

## 6. Continuity 暂时拆成四个正交问题

不要建立一条：

```text
NONE < EXACT < SEGMENT < SEMANTIC < ...
```

更合理的是分开回答：

### Axis A — Historical Dependency

```text
Did source participate in producing target?
```

例如：

```text
used
quoted
translated-from
summarized-from
trained-on
distilled-from
```

### Axis B — Preservation / Transformation

```text
What declared property or scope survives?
```

例如：

```text
byte equality
canonical equality
segment mapping
profile-defined transform
claim support relation
unknown
```

### Axis C — Coverage

```text
Which parts of source and target are covered?
```

### Axis D — Evidence / Assurance

```text
What evidence supports A/B/C and what can that evidence actually prove?
```

这样可以表达：

```text
historical_dependency = VERIFIED
exact_preservation = NONE
semantic_preservation = DECLARED_ONLY
coverage = paragraph_2_to_4
```

而不是压成一个 `CONTINUITY_LEVEL_3`。

## 7. F0 第五项关键结论：Evidence 必须有 proof boundary

每个 Evidence Profile 必须明确：

```text
what it observes
what claim types it can support
scope
freshness / time
issuer / observer
assumptions
known failure modes
what it cannot prove
```

例如：

### Cryptographic signature

可以支持：

```text
this signer signed this claim/record
```

不能直接支持：

```text
the claim is objectively true
```

### Hard content binding

可以支持：

```text
this record is bound to this representation/state
```

不能直接支持：

```text
this actor authored all underlying ideas
```

### Watermark / fingerprint

可以支持：

```text
a signal matching profile P was detected
```

不能自动支持：

```text
provider identity proven
legal ownership proven
```

### Semantic similarity

可以支持：

```text
algorithm M measured similarity score x
```

不能自动支持：

```text
derivation occurred
plagiarism occurred
training relation proven
```

### Hardware attestation

可以支持由其 measurement / appraisal profile覆盖的运行环境事实。

不能自动支持：

```text
output factual truth
copyright legality
```

## 8. 新的候选基础架构

F0 Round 1 不再推荐：

```text
Entity
Relation
Continuity
Evidence
```

作为冻结四原语。

新的候选 **Information Model** 是：

```text
Subject / State
      │
      ▼
Claim
  ├─ proposition
  │    ├─ property
  │    └─ relation
  ├─ scope
  ├─ context/time
  └─ asserted/observed/inferred by
      │
      ▼
Evidence
      │
      ▼ appraisal
Assessment / Verification Result
      │
      ▼ local policy
Decision / Presentation
```

其中：

- `Relation` 是 proposition vocabulary，而不是未经限定的事实边；
- `Continuity` 是一种 **scoped relation/preservation claim family** 或 verifier query result；
- `Evidence` 与 `Assessment` 分离；
- `Decision` 永远位于 Core 事实层之外。

## 9. 候选 Claim 结构

仅作为研究伪代码：

```text
Claim {
  claim_id
  proposition {
    predicate
    subject_ref
    object_ref_or_value?
  }

  source_scope?
  target_scope?
  projection_profile?
  context?
  temporal_context?

  claim_origin {
    asserted | observed | inferred | reconstructed
  }

  claimant?
  evidence_refs[]
}
```

注意：

- `claimant` 不等于 proposition 里的 actor；
- `asserted_by` 不等于 `generated_by`；
- verifier 可以评估 Claim，而不是把 Claim 直接当真。

## 10. 候选 Assessment 结构

```text
Assessment {
  claim_ref
  evidence_refs[]
  verifier_ref
  verification_profile
  time

  result {
    supported
    contradicted
    indeterminate
    invalid_evidence
    unsupported
  }

  verified_scope?
  assumptions?
  diagnostics?
}
```

这里的状态仍需进一步研究，尤其不能把 `unsupported` 解释成 `false`。

## 11. Claim Graph，而不是 Fact Graph

候选图：

```text
State A
   │
   │ Claim C1: quoted-from, scope A3 -> B2
   ▼
State B

Evidence E1 ─supports─> C1
Evidence E2 ─challenges─> C1
Assessment V1 ─assesses─> C1
Claim C2 ─supersedes─> C1
```

这样可以自然表达：

- 多来源；
- 局部来源；
- 冲突；
- 更正；
- 撤回；
- 独立 verifier 不同判断；
- 不同时间点的 Evidence。

## 12. Event / Activity 是否必须成为 Core primitive？

尚未决定。

W3C PROV 把 Activity 设为核心是有充分理由的，因为：

```text
source --used-by--> activity --generated--> target
```

比单一 `derived-from` 能表达更多因果结构。

但 GCPP 需要进一步测试：

- Event 是否可以作为一种 Subject/State；
- relation proposition 是否足够表达 execution；
- 对 AI Agent、训练 run、生成 execution 来说，是否需要标准化 Event lifetime / inputs / outputs；
- 如果需要，Event 应成为 Core role 还是 Profile。

因此本轮不删除 Activity/Event，只把它列为 F0 下一项必须解决的问题。

## 13. 本轮被证伪/降级的假设

### 被证伪：Continuity 是单一全局等级

不能成立。

### 被证伪：内容相似可以单独建立 provenance

不能成立。

### 被证伪：Evidence 可以直接等于最终信任判断

不能成立。

### 被降级：Relation 直接作为事实图边

应优先放入 Claim proposition。

### 新增候选：Claim

目前显示出强必要性。

### 新增候选：Scope qualification

目前显示出强必要性。

### 新增候选：Assessment

很可能是跨 Evidence 技术实现互操作的关键输出层。

# English

## Round 1 finding

The original `Entity / Relation / Continuity / Evidence` hypothesis is insufficient.

GCPP should treat provenance primarily as an **evidence-backed claim graph**, not as a graph of unqualified facts. A first-class Claim is needed because provenance statements may conflict, be retracted, be superseded, be reconstructed, or be assessed differently by independent verifiers.

`Continuity` is not a global scalar or ladder. It is meaningful only relative to a source state, target state, source/target scopes, a projection/facet or comparison profile, a claimed historical/transformation relation, and supporting evidence.

The current research model therefore becomes:

```text
Subject / State
      ↓
Claim (property or relation + scope/context)
      ↓
Evidence
      ↓ appraisal
Assessment / Verification Result
      ↓ local policy
Decision / Presentation
```

Historical dependency, preservation/transformation, coverage, and evidence assurance must remain orthogonal. Similarity does not prove derivation; a training dependency does not imply that a particular model output preserves a specific training sample; a signature proves signing, not objective truth.

The next F0 round must determine whether Scope and Event/Activity deserve Core primitives and must formalize claim conflict, correction, retraction, privacy-preserving disclosure, and multi-verifier assessment.
